Мета роботи

Знайомство з порядком застосування, завантаження, встановлення та налагодження системи контролю версій Git і навчання використанню основних інструментів GitHub.

Хід роботи

1 Встановлення та налаштування Git

Використано Git for Windows (версія 2.56.0) з оболонкою Git Bash. Для репозиторію задано ім’я автора і e-mail (git config user.name / user.email), основну гілку названо master (git init -b master).

2 Робота з локальним репозиторієм

Репозиторієм обрано каталог з усіма лабораторними роботами. Послідовно виконано дії з методичних вказівок: ініціалізація (git init), створення файла example.txt і перегляд стану (git status), додавання файла під контроль версій (git add) і фіксація (git commit -m 'Added file'), видалення файла (git rm) і фіксація, створення та перехід на гілку development (git checkout -b development), додавання всіх файлів лабораторних робіт і коміт, перегляд історії (git log). Далі гілку development злито в master, створено гілку edit-readme-file, змінено README.md, переглянуто відмінності (git diff), зафіксовано зміни, злито гілку в master командою git merge --no-ff (аналог Merge pull request на GitHub) і видалено злиту гілку.

4 Робота з GitHub

Для виконання другої частини роботи на GitHub необхідно: зареєструвати обліковий запис; натиснути New repository, вказати назву (напр. algorithmization-labs), опис, позначку Initialize this repository with a README і натиснути Create repository; створити гілку edit-readme-file через список Branch: master; змінити README.md (іконка олівця) і виконати Commit changes; на вкладці Pull requests натиснути New pull request, вибрати гілки master ← edit-readme-file, переглянути зміни (зелене — додано, червоне — вилучено), натиснути Create pull request, потім Merge pull request → Confirm merge → Delete branch.

Локальний репозиторій, створений у цій роботі, публікується на GitHub командами:

git remote add origin https://github.com/<логін>/algorithmization-labs.git
git push -u origin master

Посилання на репозиторій: https://github.com/<логін>/algorithmization-labs (вказати після публікації).

Висновки

Ознайомилися з основним функціоналом системи контролю версій Git: створенням локального репозиторію, індексацією та фіксацією змін, видаленням файлів, створенням і перемиканням гілок, переглядом історії та відмінностей, злиттям гілок. Розглянуто роботу з сервісом GitHub: створення репозиторію, гілки, коміт змін через вебінтерфейс, Pull Request і Merge.

Відповіді на контрольні питання

1. Для чого потрібні системи контролю версіями (СКВ)? Для зберігання історії змін файлів проєкту, повернення до будь-якої попередньої версії та спільної роботи кількох розробників над одним кодом.

2. Які завдання виконують СКВ? Зберігання файлів у репозиторії, збереження всіх ревізій, журнал змін (хто, коли, що змінив), робота з гілками, злиття змін, виявлення конфліктів і синхронізація між учасниками.

3. На які групи за архітектурою побудови поділяються СКВ? Локальні, централізовані (CVS, Subversion) і розподілені (Git, Mercurial).

4. Що таке «Робоче дерево»? Каталог з файлами поточної версії проєкту, з якими безпосередньо працює розробник (робоча копія).

5. Пояснити термін «коміт». Коміт — зафіксований знімок стану індексованих файлів з унікальним ідентифікатором (хешем), автором, датою та повідомленням, що пояснює зміни.

6. Пояснити терміни Checkout та Merge. У чому їхня різниця? Checkout — перемикання робочого дерева на іншу гілку або ревізію; Merge — об’єднання змін з іншої гілки в поточну. Checkout змінює те, з чим ми працюємо, а merge створює нову спільну версію.

7. Як створити локальний репозиторій? Перейти в каталог проєкту і виконати git init.

8. Як видалити файл з репозиторію? git rm файл, а потім git commit.

9. Як отримати історію ревізій за будь-яким файлом у репозиторії? git log -- файл (з ключами --stat, -p для деталей змін).

10. Що таке GitHub? Вебсервіс для хостингу Git-репозиторіїв і спільної розробки: pull request, рецензування коду, задачі, вікі, CI.

11. Які системи контролю версій підтримуються в GitHub? Git (раніше також надавався доступ через Subversion).

12. Яким чином створюється нова гілка в репозиторії на GitHub? У списку гілок (Branch: master) ввести назву нової гілки і вибрати Create branch.

13. Як додати зміни до репозиторію? Локально: git add і git commit, потім git push; на GitHub — редагування файла і кнопка Commit changes.

14. Як називається основна гілка репозиторію? master (у нових репозиторіях GitHub — main).

15. Яким чином можна перевірити відмінність контенту в гілках? Командою git diff гілка1 гілка2 або на вкладці Pull request (Compare) на GitHub.

16. Як називається команда злиття гілок? git merge.
